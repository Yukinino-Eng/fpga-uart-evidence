# 03：实现建议、离板自检与交回

## 实现顺序

1. 先做单帧：0xA5/0x5A包头、小端负数、48字节长度、CRC正确；TX空闲高，两个输出完全相同。
2. 再做100ms槽调度与连续正常发送。只有UART接收握手后才能推进字节地址，停止位不能截断。
3. 加入场景选择、故障修改和时长选择。开关两级同步，S0去抖；修改字段后重算CRC，只有bad_crc在正确CRC后故意翻转一位。
4. 添加自己的自检testbench，从TX线按8N1独立采样，导出实际接收字节与帧起始周期，再运行包内比较工具。
5. 最后再生成bit、检查100MHz时序/DRC/CDC和资源。当前阶段不需要连接PYNQ或板卡烧录。

可以按fixture的`bytes.mem`和`schedule.mem`做ROM重放，也可以实时计算帧和CRC。八个20秒10Hz场景的原始ROM总量约76.5KB（断流少6帧），**不要为两档波特率各复制一套相同字节ROM**。长模式不能简单循环20秒ROM并重置序号；可在后半段实时生成正常帧，或在构建时选择单场景长向量。EGo1 BRAM有限，应以综合报告为准；不要把全部60/180秒、所有速率与场景向量无选择地综合进同一bit。

`schedule.mem`使用64位绝对周期；60秒在100MHz下是60亿周期，32位计数器只能覆盖约42.95秒。时长计数、槽目标时刻和相关比较至少使用64位，或使用经验证的分级计数，不能静默回绕。

参考`uart_tx.sv`的BAUD是编译参数。需要运行时两档时，可编写可配置分频器，或用两个固定速率发送器并且只启动所选实例，输出在空闲时切换；不能仅改变LED而未改变串行位周期。综合时使用同步BRAM读口、正确处理1周期读延迟，避免大块异步读ROM变成大量LUT。

## 工程模板

`reference/create_project.tcl`是创建工程模板：期望你把新顶层及附属模块放在包根`src/`，顶层模块名`ego1_urx2_source_top`；端口采用参考XDC中的`sys_clk/fpga_reset/button_s0/switches[4:0]/uart_tx_o/gpio_tx_o/leds[7:0]`。模板在没有新源码时明确拒绝运行，不是假装存在的完整工程。

该模板仅创建工程，不自动生成bit、不下载或写Flash。若改模块/寄存器名，需更新同步器约束，并确认CDC及未约束端点，不可用整片false_path隐藏内部问题。ROM文件请在自己的源码中使用相对路径或构建脚本传入的明确路径，同时交回所需初始化文件。

## 至少应交回的内容

| 内容 | 要求 |
|---|---|
| HDL源码 | 顶层、调度/编码/CRC/ROM模块及实际使用的复用文件；注明哪些是原参考文件 |
| 工程入口 | 可从干净目录创建/构建的Tcl或明确操作步骤，器件与100MHz约束正确，无个人电脑绝对路径 |
| testbench | UART线独立接收检查、运行脚本、实际结果日志；两档波特率、正常及八个P0场景 |
| 对照数据 | 每场景`received.bin`、`frame_starts.csv`、工具生成的`check.json`；标明仿真或实板来源 |
| 构建结果 | bit及SHA256、Vivado版本、时序/资源/DRC/CDC报告；没运行的项目注明待做 |
| 简短说明 | 开关、按键、LED映射、帧率/时长选择方法、已知问题；不需要比赛报告 |

如果尚未拿板，交回“源码＋通过的离板自检”即可，实板栏保持待完成。不要把本包的`checks/`结果复制成自己新RTL已通过的证明。PYNQ新固件的100MHz建立余量很紧；出现实线问题时保留发送日志与原始字节，双方共同定位，不先归因给某一块板。
