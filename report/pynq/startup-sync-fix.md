# URX2 持续遥测中途启动修复（2026-11-01）

## 问题与修复

旧URX2将UART解码器复位与采集开关、会话清除绑定。发送端持续工作时，如果在字节内部开启接收，就可能把数据位当作起始位，随后产生一次人工引入的停止位错误。该错误又会触发原有采集保护，影响硬件解析。旧实现已在XSim稳定复现：0x00正常UART流、半位偏移开启，在114.350µs观察到停止位错误。原失败日志、波形与旧RTL快照保留。

startup2让UART解码器在停止采集时仍跟踪线路，采集开关只控制完整字节是否进入FIFO。会话清除不会打断UART字节状态机；实际更换波特率或外围复位时才重置UART。配套驱动在更换波特率后先完成有界同步等待，再开始计入新会话。正常停止位错误检测保留，没有忽略错误计数、关闭保护或更改设备协议。

ID仍为`0x32585255`，ABI仍为2.0；能力寄存器新增bit9，startup2读回`0x3ff`，表示后台UART同步。基础能力位不变，驱动仍支持旧URX2，并按实际能力标记`uart_sync_policy`。只允许从明确摘要的已知URX2、已验收旧基线或匹配镜像安全更换，仍检查身份、停止状态、原始FIFO、事件FIFO和解析器状态。

`scripts/generate_urx2_shell.py`已同步更新，`--check`确认生成结果与验收RTL完全一致。URX1/CAR1旧基线的RTL不改写。
