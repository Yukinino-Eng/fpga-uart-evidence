## 配置与硬件分工

- 实线接线：EGo1 J5物理15脚/B11 → PYNQ PMODA物理1脚/Y18；J5物理33或34脚GND → PMODA物理5或11脚。小车PA9已由用户确认移除，两个发送端未并接。
- EGo1加载LAB文本版，输出`@LAB,seq,ms,temp_mdeg,voltage_mv,status*HH\r\n`，10帧/秒。温度与电压是ROM生成的测试数值，不是另一台真实传感器的测量。
- PYNQ文本配置为`profiles/lab_ascii_v1.json`，执行模式为“软件规则 / URX2通用”：FPGA继续提供UART、逐字节硬件时间和FIFO，PS完成文本解码与规则。小车二进制模式的8路硬件规则仍属于同一个bit，切回时重新提交配置即可。
- 所有本轮记录的`reprogrammed`均为false。PYNQ bit SHA256为`24870758d42c9abcbf5bf7ffc631dfbfb8de886d512fd5d10e403cfdfae4106f`；HWH为`f6f7ab1713720150fc2dccd42cfc31d2c9fdb47c84bec42999d50f3172421edf`，与真实小车联合记录一致。
- 时间仍是100MHz相对硬件计数，板上系统时间未经独立校准，不将其当作UTC证明。

## 发送固件核验和复现

EGo1 bit为`build/ego1_lab_source/firmware/ego1_lab_source.bit`，SHA256为`6fa75881e231c4d33fb7168a9c2fe81d819ea7d332e5843261b5a3066b5c959a`。RTL、ROM、约束和bit与原准备版一致。Vivado确认唯一目标为XC7A35T，并报告配置启动状态HIGH；只加载运行配置，未写入Flash。EGo1断电后如需继续LAB测试，要重新临时下载该版本。

原准备清单同时封存了早期PYNQ软件，因11个接收端/界面相关文件后来更新，旧整包校验拒绝运行，失败结果保留。没有改写旧清单：重新核对115个当前文件，确认所有EGo1构建输入与bit未变、线协议定义和规则与封存包一致，并通过6项发送源及79项UART软件检查，另存`revalidated_manifest.json`。实际烧录前通过`verify_revalidated.py`再次逐文件验证；下载仍使用原脚本的唯一目标与器件型号检查。工具MCP启动器在产生Vivado输出前退出，本次采用原生Vivado2025.2批处理。

后续重复下载前，在项目根目录先执行本轮目录中的`verify_revalidated.py`；若源码继续变化，应另做新日期的核验，不能强改旧摘要。JTAG只允许确认的XC7A35T目标；不向PYNQ下载EGo1文件。

本轮不生成新的队友交付ZIP，不改变小车程序、控制参数、SD启动镜像或QSPI。物理过载、保存失败恢复和最新整机断电恢复仍是后续验收项。

## 界面与结束状态

实际登录原板Notebook，选择LAB协议、“软件规则 / URX2通用”和115200，配置检查及五个LAB字段预览通过；打开本轮实际保存的600帧记录，身份仍为URX2、协议检查通过。另在组合回放中验证LAB五字段、真实小车十三字段及离线样例四字段随协议切换，离线样例正确显示“不具备判断条件”，浏览器无脚本错误。

结束时PYNQ仍为startup2、115200，接收关闭，原始FIFO及事件FIFO为空，文本硬件解析器旁路。两个电脑串口接收进程、两个板端采集进程和Notebook本轮刷新均已停止；没有发送任何小车控制命令。
