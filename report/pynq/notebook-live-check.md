# Notebook实时联合检查

本页记录工程检查过程，不是赛题提交报告。

2026-11-01使用startup2固件与未修改的小车遥测程序，实际打开板端经典Notebook浏览器页面，完成300秒联合采集及修正状态文字后的60秒复测。工程收据为`build/uart_live_run_20261101/completion.json`，实际回放入口为[小车运行与实时界面实测](../../deliverables/URX2_小车运行与实时界面_实测_20261101.html)。

## 最终结果

- 联合采集300.045秒、15028帧、721344字节；CRC、缺号、重复、停止位错误和各级硬件溢出均为0；原始文件校验、电脑逐字段解码及事件回放一致。
- 5245帧的控制运行标志连续置位，观察区间为首帧后67.534893–172.207363秒，跨度104.672471秒；其中352帧驱动使能关闭且两路PWM均为0，不能把驱动使能间歇视为控制程序退出。控制期间倾角范围为-1.517°至0.548°。这里只记录原车算法输出，不评定传感器绝对精度。
- 最后控制活动后保留6400帧、约127.77秒；全部两路PWM为0、运行及驱动使能关闭。用户明确反馈运行状态好、两轮已完全停住；这类机械观察与遥测分别保留。
- 主机队列最高40/1024；Notebook实际浏览器持续读取267个实时样本、202次观察到新帧，没有页面脚本错误或超过3.5秒未更新提示。采样观察约每秒一次，不能由此声称500ms刷新时限获得保证。
- 联合采集曾观察到6个错误的页面超时标签，硬件超时事件为0。修正显示依据后另做60.050秒静态复测：3006帧、无通信和采集错误；54个实时浏览器样本没有错误超时标签或更新延迟提示。停止时26字节尾部残帧如实保留。修正不改变固件、检测规则或采集路径，因此未要求用户再次运行电机。
- 电脑79项检查、原板Python3.6环境34项检查和旧版组件实际嵌套显示检查通过。原生浏览器验证真实超时及恢复仍正确显示。结束时接收关闭、原始FIFO及事件FIFO为空，本次Notebook定时刷新与浏览器测试已停止；固件保持startup2。

本轮使用小车基础规则，没有故障窗口，未验证大量窗口同时显示的最大页面负载。URX2同bit文本实线随后已完成，见[双协议检查](same-bit-text-check.md)；物理存储/过载边界和最新完整断电恢复仍作为后续项目；未将本轮通过扩大为所有验收已完成。

## 本轮修复

实际浏览器发现，原来在`ipywidgets.Output`中动态显示的嵌套可视化没有出现在旧版Notebook页面中。改为显式设置VBox的子组件；独立取证查看器仍可单独显示，协议、记录切换继续使用同一渲染器。

第二轮静态采集保留3610个完整帧，但原来的全量JSON反复传输造成页面延迟。本轮改为每500ms尝试刷新，较大的完整快照使用Python标准库zlib无损压缩、Base64传输，浏览器通过`DecompressionStream('deflate')`恢复。每次都是完整快照，不依赖前次更新，不会因中间页面消息跳过而漏接增量。原始流、解析记录、时间、事件及窗口文件格式未改变。

实时压缩视图要求支持`DecompressionStream`的新版Chrome或Edge；不支持时明确显示提示，不默默显示旧数据。独立导出的HTML仍嵌入普通JSON，不依赖该解压接口。500ms为目标刷新间隔，实际刷新速度按原板与浏览器实测记录，不承诺硬实时页面刷新。

电脑79项UART软件测试通过。另将实际记录的最近2000帧通过浏览器原生接口解压，逐字段与原快照一致；损坏压缩数据被拒绝。该快照原JSON约2510942字节，传输约192718字符。这是该记录的测量值，不能推导任意协议、任意事件数下的固定压缩比或吞吐上限。

首轮`car_tlm1_ae61c0baddb3`采集28.42秒、1414帧；第二轮`car_tlm1_f5568f98689b`采集73.13秒、3610帧。两轮原始文件摘要、电脑逐帧解码及事件回放均通过，但均为提前停止的界面诊断，不能代替180秒联合验收。两轮所有帧的控制运行和驱动使能均关闭；用户在这两轮之外反馈的平稳运行不补记进原始数据。

联合测试期间发现，页面曾仅凭已解析帧的时间差显示“有效帧超时”，而同一时刻硬件没有断流事件。存在待处理数据时，该时间差不能单独证明设备断流。现改为使用检测引擎的活动超时状态，或晚于最新有效帧的实际超时事件；收到后续有效帧后恢复显示。浏览器检查同时覆盖处理延迟不误报、真实事件提示、软件活动状态提示及新帧恢复，没有修改检测阈值或硬件事件。

## 联合检查口径

同时保留实际Notebook页面刷新测量与采集记录，不能以命令行加静态导出页面代替。用户按原车按钮控制启停，PYNQ仅接收。遥测运行标志、PWM及编码器变化作为数据证据；实际平衡及车轮停止需要用户观察确认。硬件计数为相对时间，板上未核准的系统时钟不作为真实UTC证据。

本轮不写入新的小车程序，不改控制参数、SD启动镜像、QSPI或Notebook认证配置。旧发行目录与历史失败记录保留。
