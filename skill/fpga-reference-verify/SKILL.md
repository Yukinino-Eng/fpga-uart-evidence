# FPGA 参考模型与分阶段回归

## 用途与适用场景

用于 FPGA 算法、协议和数据通路改动后的回归。核心是独立参考及明确阶段：仿真通过、构建通过、实板通过与历史回放通过分别说明，不能互相替代。

## 输入与前置条件

需要本次改动、参考模型或协议契约、测试输入、比较容差、工具版本和目标器件。参考由算法规格、独立实现或已核验样例建立；接口桥接也可用协议约束和记分板，不要求必须有数值黄金模型。

## 执行步骤

1. 先确定期望、容差和边界输入，保留参考来源及版本；避免被测实现和参考共享同一错误推导。
2. 仿真阶段比较数据、时序/握手和错误行为，报告首个差异与对应激励。工具异常退出必须保留为未完成或失败，不能当作功能通过。
3. 构建阶段记录源码、约束、工具、时序与 DRC。bit 文件摘要与配置载荷摘要不是同一概念；构建产物不同需解释，不预设所有工具构建都逐字节相同。
4. 实板阶段绑定实际加载的版本和原始日志；没有板卡则明确未执行。新的实现或配置不能仅继承旧版本实板结论。
5. 回放阶段从原始数据重算字段、完整性和事件，保留无法比较的原因。流水入口按当前任务选择阶段，不因存在 Stage all 就强制每次全量重建。

## 失败条件与处理

差异、超时、缺少输出或工具崩溃均保留输入与日志。不能为了消除差异倒改验收期望；参考确有独立证明的错误时，单独修订契约并说明依据，再重跑受影响用例。

## 输出与验收

分别给出 simulation、build、hardware、replay 的 PASS/FAIL/未执行及版本依据。正常输入与有意义的边界通过；受控错误必须被参考或协议检查检出。重放已有实测仅证明记录可复核，不等于重新完成同一实板测试。

## 来源与已验证效果

旧稿由 Vivado 导出后异常退出和新 bit 误沿用旧 PASS 的风险提炼。历史重建收据 `build/pynq_z2/full_reproduction_receipt/report.json` 分别记录了两版设计的时序、DRC、配置载荷一致及 hardware_programmed_in_this_reproduction=false；配套 orchestration.json 记录 Stage all 的退出码 0。本轮没有重建 SBB 或 URX2；UART 历史回放另见本包验收记录。

## 迁移边界与关联资料

参考形式和比较精度随题目选择，不能把当前样本数、帧率与固定阈值当作通用判据。历史收据摘要见整包 [source-index.json](../source-index.json)。
