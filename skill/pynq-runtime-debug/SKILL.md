# PYNQ 运行环境与工具排错

## 用途与适用场景

用于“SDK 导入失败、同一脚本换入口不工作、仿真异常退出、时间不可信或旧固件混入”等问题。先确认执行环境，不把所有现象归因于 RTL 或被测设备。

## 输入与前置条件

需要报错原文、实际入口/解释器、操作系统与板卡镜像、SDK/工具版本、日志和最近变更。只做环境检查时不加载位流、不改设备控制参数。

## 执行步骤

1. 记录实际解释器路径、版本和 SDK 导入来源，再核对权限。某旧镜像曾使用 /opt/python3.6/bin/python3.6；这只是实例，不是其他 PYNQ 的固定路径。
2. 区分语法兼容、依赖可导入与真实运行兼容。选择目标环境支持的缓冲区/Overlay API，不因主机 Python 通过就宣称旧板端通过。
3. 仿真工具异常退出时保留退出码与最小输入。Windows vvp 的 0xC0000005 表示进程访问异常，单凭它不能证明 RTL 正确或错误；可缩小用例并用合适的另一仿真器交叉定位。
4. 区分硬件相对计数、设备自身时间和系统墙上时钟。无授时时标为未核验，跨重启分会话；历史错误时间不回写“修正”。校时方法和有效期由项目定义。
5. 依版本摘要定位实际固件，错误旧版保留历史并标清用途。对测得的延迟说明起点/终点、时钟和样本分布；未测的分位数或吞吐不补造。

## 失败条件与处理

无法确定解释器、身份、时间来源或工具退出原因时保留不确定性。替换工具得到的通过是新的结果，不能抹除原失败；安装或修复后至少重跑原失败入口。不要把某目录命名偏好或其他赛题的指标当作所有环境的强制要求。

## 输出与验收

输出环境摘要、可复现入口、失败日志、采取的改动和修复后结果。未取得修复后运行证据时只报告定位进展。依赖安装不能等同于功能恢复。

## 来源与已验证效果

旧稿记录了板端解释器选错、Windows vvp 崩溃、系统日期异常与旧固件并存。本轮新技能工具在主机 Python 实际执行，但没有新增板端 Python3.6 实测；实际版本和结果见根 validation.json。历史工具问题作为排查案例保留，不宣称在所有系统复现或已普遍修复。

## 迁移边界与关联资料

替换为目标系统的解释器、SDK、权限和时间机制。固件操作采用项目既有的身份与独占契约；环境排错不授予额外硬件操作权限。旧稿及历史环境来源摘要见整包 [source-index.json](../source-index.json)。
