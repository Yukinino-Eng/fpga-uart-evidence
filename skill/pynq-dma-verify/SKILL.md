# PYNQ DMA 采集完整性核验

## 用途与适用场景

用于 PL 数据流经 DMA 进入 DDR，或 CPU 缓冲区经 DMA 送往 PL 的项目。先判断搬运是否正确，再评价数据内容；本技能不替代带宽设计。

## 输入与前置条件

需要传输方向、SDK/驱动版本、缓冲区分配方式、是否缓存一致、帧契约及可核对的数据源。帧契约应说明长度、序号、校验和边界；没有某项能力时标为不具备判断条件。

## 执行步骤

1. 按驱动分配 DMA 可用内存。不同 PYNQ 版本可能使用 allocate 或 Xlnk/cma_array，不能把普通 numpy 数组当作物理连续 DMA 缓冲区。
2. 明确 CPU 与 DMA 的所有权交接。非一致性缓冲区在 CPU→PL 前按契约 flush，在 PL→CPU 完成后、CPU 读取前按契约 invalidate；先检查驱动是否自动维护缓存。DMA 持有缓冲区时不改写、释放或复用。
3. 等待完成后核对实际长度、帧边界、序号与校验，独立统计残帧、丢帧、重复和校验错误。校验算法、覆盖范围及大小端由协议规定；双 CRC 是本项目实例，不是所有设备的前提。
4. 将“传输帧不完整”和“异常事件的前后窗口不足”分开标记。残帧不冒充完整帧，但原始字节、时间及错误现场仍应保留。
5. 保存失败时保留待处理结果并报告容量/重试状态；内存不足或保存队列满时明确记录丢失，不能承诺无限缓存。

## 失败条件与处理

缓存所有权不明、超时、长度不符、序号断裂或校验错误时，不把该传输报告为完整。故意注错的验收可以在“正确检出错误”时通过，但被测记录的完整性失败仍要保留。持续输入超过排空能力时先解决背压/带宽/缓冲，不能靠校验消除过载。

## 输出与验收

输出传输方向、缓冲区策略、请求/实际长度、各类完整性计数及保存状态。用已知源逐帧或逐样本对照；正常数据和受控缺损分别按预先声明的期望核验。

## 来源与已验证效果

来源于旧 SBB/DMA 稿的缓存、残帧和保存恢复观察。现存 SBB5 汇总收据记录：受控片内源 60 秒、6000 万样本、234375 帧，原始 CRC 为 157dc93d，特征 CRC 为 2bcdbeaf，状态 PASS，real_device_input=false。来源为 `build/pynq_z2/final_extraction_r4/validation_summary.json`。本轮只核对历史收据，不重新执行 DMA 验收；这些数字不能说明当前 UART 或任意外接设备达到 1 MS/s。

## 迁移边界与关联资料

迁移时替换 DMA 通道、驱动、缓存策略及帧格式。低速寄存器读取不必套用该流程。来源摘要见整包 [source-index.json](../source-index.json)；原始 SBB 数据仍在完整工程中。
