# 案例：把专用小车监测收敛为可配置平台

这是根据真实会话与现存工程材料整理的决策案例。用户引文来自本次会话，工程处理是事后归纳，不是模型原回答，也不是完整聊天导出。

## 问题怎样提出

用户指出：“检测固件必须配套，我们能不能做出一个通用点的接口，做到小改动就能实现检测，这也是这个项目的价值点”。后续又要求：“赛题截止在即，我们需要加速干了，不能等到有确切需求时再做了”。

当时需要回答的不是单个寄存器怎样写，而是：专用固件带来的接入成本如何降低、如何证明复用、有限时间先验证什么。

## 已采用的范围与理由

- 通用接口计划明确选择单通道 UART、配置化定长二进制/换行文本、规则与前后取证；复杂格式保留解析插件接口。SPI/I²C、自动猜协议和设备控制不进入首版。
- FPGA 与 PS 分工保持清楚，业务协议与规则通过配置表达；既有小车程序继续作为接入基线。后续 FPGA 规则集成单独形成 URX2 版本。
- 用已有真实小车证明实际接入，用可控文本发送器证明另一种格式可以复用同一 PYNQ 固件。EGo1 后来作为合成测试源使用；这是后续任务安排，不能把早期平台切换文档中“EGo1 不再作为前置条件”误读为永久禁止测试源。
- 板卡暂时缺席时先完成接口、向量、仿真和软件回放；拿到板后补实线验证。阶段状态分别保留，未用离板记录替代实线。

## 可以核对的结果

`build/uart_text_acceptance_20261101_01/completion.json` 记录同一 startup2 固件接收 LAB 文本：9600 与115200两档各600帧，板端数据、电脑独立接收和发送向量一致；小车二进制记录与同一固件摘要的对应见 `deliverables/urx2_verified_version_20261101_v1.json`。这支持“已测两种协议可配置复用”，不支持“所有设备均可直接接入”。

`docs/non-device-development-plan.md` 保留了无板阶段先准备、设备就位后补测的方法来源。它属于较早 SBB 阶段；其1MS/s等数字不能用来描述当前外部 UART。

`deliverables/acceptance_and_scoring_checklist_20261101.md` 是阶段检查材料，其中八路与恢复的待办后来已有新收据，不能照抄为当前未完成状态；新收据与版本冻结清单应一起读。

## 可迁移的决策问题

面对“还要不要增加接口”时，可先写下面这张记录，再决定是否实现：

| 问题 | 本案例的回答 |
| --- | --- |
| 接入者目前多花了什么成本？ | 更换设备格式时需要改专用采集/检测实现 |
| 最小改变能解决什么？ | 把已支持分帧、字段和规则放入配置；复杂协议使用显式插件 |
| 怎样证明而不是口头承诺？ | 同一 PYNQ 固件接收真实二进制源和另一种合成文本格式，保存原始数据并独立复核 |
| 哪些依赖必须保留为待验？ | 未提供的真实设备、其他总线、电平和更高吞吐 |
| 怎样避免影响交付？ | 复用已验收基线，先完成配置闭环；扩展条件另行说明 |

## 来源与效果边界

来源入口为上文路径及 `docs/uart-monitor/README.md`；完整工程相对路径和摘要见整包 source-index.json。相关原始数据未随轻量技能包复制。
